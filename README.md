# Explainable AI for Credit Risk Prediction

An educational machine-learning project using the **original symbolic UCI
Statlog German Credit dataset**. It compares a Random Forest baseline with a
cross-validated XGBoost model, and uses SHAP to describe model outputs.

> **Academic prototype only.** This project is not a real credit-approval or
> lending system, does not provide financial advice, and must not be used to
> make real decisions about people.

## Dataset and label mapping

Place the official original files in `data/raw/`:

- `german.data` — 1,000 whitespace-delimited records, no header; 20 inputs and
  the target as the final field.
- `german.doc` — source documentation for the attributes and class encoding.

This project uses the original symbolic `german.data`, not the separately
edited `german.data-numeric`. The verified original target mapping is:

| UCI target code | Project label |
|---|---|
| 1 | `good-risk` |
| 2 | `bad-risk` |

For XGBoost's binary objective, the training script encodes `good-risk` as 0
and `bad-risk` as 1, then decodes results for evaluation and display.

## Setup

From the project root, create and activate a virtual environment (Windows
PowerShell):

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The verified UCI files are already stored at `data/raw/german.data` and
`data/raw/german.doc` in this workspace. If you need to download the dataset,
use the official UCI dataset page:
<https://archive.ics.uci.edu/dataset/144/statlog+german+credit+data>.

## Prepare data

```powershell
python -m src.preprocessing --input data\raw\german.data --output-dir data\processed
```

This validates the original file, preserves the existing 80/20 stratified
split (random state 42), fits the `ColumnTransformer` on training data only,
and writes the same split consumed by both experiments.

## Train and evaluate models

Random Forest baseline:

```powershell
python -m src.train
```

Primary XGBoost model:

```powershell
python -m src.train_xgboost
```

XGBoost searches a small parameter grid with three-fold stratified
cross-validation using training data only and ROC-AUC scoring. The held-out
test split is used only after tuning for the final reported evaluation.

To re-run evaluation from the saved model without retraining:

```powershell
python -m src.evaluate
python -m src.evaluate --model models\xgboost.joblib --processed-dir data\processed --report-dir reports\xgboost
```

## Generate SHAP plots

```powershell
python -m src.explain
```

The command uses up to 150 training applicants to summarize SHAP values and
up to 60 training rows for the background. It does not explain an unbounded
dataset or use the held-out test data for the global plots. For example, to
use smaller samples:

```powershell
python -m src.explain --max-rows 100 --background-size 40
```

SHAP explains the XGBoost **raw margin (log-odds) for encoded class 1,
`bad-risk`**. A positive contribution pushes the model margin toward
bad-risk; a negative contribution pushes it away from bad-risk. Global
importance uses mean absolute SHAP values and shows magnitude, not direction.
SHAP explains model behavior; it does not prove that a feature causes
creditworthiness or repayment.

## Run automated tests

Tests use the verified dataset and the actual locally trained model. Prepare
the data and train XGBoost before running:

```powershell
python -m pytest -q
```

The tests cover the target mapping and schema, reproducible preprocessing
outputs, input validation, real saved-model inference, an actual individual
SHAP explanation, and the Streamlit pages.

## Launch the website

```powershell
python -m streamlit run app.py
```

The local address is normally `http://localhost:8501`. For a hosted deployment,
configure the host platform to run `python -m streamlit run app.py` from the
project root. Run the preprocessing, training, and SHAP commands before
deployment so the required local artifacts exist.

The app uses a dark navy visual theme and sidebar navigation. Its dashboard
shows dataset details and saved model metrics only when those files are
available. The app loads only the project-local model generated by
`src.train_xgboost`.
**Never load an uploaded or otherwise untrusted Joblib artifact**: deserializing
Joblib files can execute code.

## Interpretation and limitations

Precision, recall, and F1 use binary averaging with `bad-risk` as the positive
class. ROC-AUC is computed from the model-estimated bad-risk score. Probabilities
are classifier outputs and are not calibrated lending odds. Results are limited
to one historical dataset and one held-out split; they do not establish
real-world performance, fairness, or causality.
